现有国际化和网站基础实现通过。

现在进入下一阶段。

这不是一次“重新设计网站”的任务。
当前网站的 UI、视觉系统、Home / Explore / Pack / Template / Free / Library 等页面整体方向已经满意。

不要推倒重做。
不要把高级感做丢。
不要为了新增功能把现在的网站改成普通 SaaS Dashboard。

接下来要做的是：

在现有“高审美 AI 模板商店”基础上，
把产品升级成：

========================================
高审美 AI 创作模板商店
+
专业 AI Recipe / 配方库
+
在线图片生成工作台
========================================

核心产品理念：

我们不是最大的 Prompt 网站。

我们不追求：
更多 Prompt
更多模型
更多功能
更多创作者

我们的价值是：

从混乱、无序、质量参差的 AI 创作内容中，
筛选、测试、优化、组织真正值得使用的东西。

品牌原则：

LESS, BUT BETTER.

少一点。
好很多。

我们卖的不是一段 Prompt 文本。

我们卖的是：

审美判断
+
专业知识
+
模型测试经验
+
可复现的方法
+
高质量结果
+
持续维护

最终用户购买的是：

“我也可以做出这种感觉。”

========================================
一、品牌与选品原则
========================================

网站定位更接近：

AI Creative Curated Store
AI Recipe Store
AI 创意买手店

而不是：

Prompt Marketplace
Prompt 搜索引擎
Prompt 大卖场
AI 工具导航
创作者自由上传市场

第一阶段继续坚持：

100% 自营精选。

暂时不要开放任何人自由上传商品。

未来如果有 Creator Ecosystem，
只能考虑：

邀请制
审核制
签约制

原因：

我们最重要的资产是质量统一和审美信任。

不能因为扩大数量破坏品牌。

所有 Template / Pack 上架前至少满足：

1. 视觉结果足够好
2. 有明确使用场景
3. 经过真实模型测试
4. 用户能够较容易复现
5. 最好可以替换成“用户自己的内容”
6. 有足够高的审美和创意价值

如果只是：

漂亮但没用途

不上。

如果：

有功能但结果很廉价

不上。

如果：

网上到处都是、没有筛选价值

不上。

========================================
二、Prompt 不再是唯一交付物
========================================

以后一个 Premium Template 不应该只包含：

一段 Prompt。

应该逐渐升级成：

Recipe / 创作配方。

Recipe 可以包含：

- 最终效果图
- 输入图示例
- 主 Prompt
- Variables
- Negative Prompt（仅适用模型使用）
- 模型建议
- 已测试模型
- 构图方案
- 镜头语言
- 灯光方案
- 色彩方案
- Styling Notes
- 参数预设
- Image-to-Image 强度建议
- Reference 使用方式
- Variations
- 常见失败结果
- Failure Fix
- Tips
- Workflow
- 多宫格方案
- 封面方案
- 下载资源
- 在线生成入口

注意：

不是每一个 Template 强制拥有所有字段。

根据模板本身使用需要决定。

但数据结构必须支持未来这些能力。

========================================
三、专业知识层
========================================

模板质量不能只依靠：

“Prompt 写得长”。

未来 Recipe 要允许融入真正的专业领域知识：

Photography
Advertising
Art Direction
Graphic Design
Brand Design
E-commerce Visuals
Film Language
Lighting
Composition
Styling

例如摄影模板：

不能只是：

85mm
cinematic
shallow depth of field

而应该有真正合理的：

为什么使用这种焦段
光线方向
光比
人物与背景距离
主光 / 边缘光
景深
材质表现
构图逻辑
背景选择
色彩控制

这些知识可以：

1. 编入内部 Prompt
2. 转化成用户可理解的 Tips
3. 转化成默认参数
4. 转化成模型调用参数

我们的长期资产：

不是某一句 Prompt。

而是：

审美判断
+
专业知识
+
模型经验
+
测试结果。

========================================
四、两种核心生成类型
========================================

模板以后至少区分：

TEXT_TO_IMAGE

和：

IMAGE_TO_IMAGE

第一类：

Text → Image

用户输入：
文字
主体描述
产品描述
人物描述
其他 Variables

然后生成。

第二类更重要：

Image → Image

用户上传：

自己的自拍
自己的商品
自己的包装
自己的房间
自己的角色
自己的参考素材

然后套用 Template / Recipe。

核心体验：

“我喜欢这个效果。”

↓

“把这种感觉换成我的。”

不要营销：

100% 一模一样复制。

不要承诺：

Exact Recreation
1:1 Guaranteed

因为生成模型存在随机性。

推荐文案思想：

Recreate the look with your own image.

中文：

把这种感觉，换成你的。

========================================
五、第一阶段只验证两个在线生成场景
========================================

不要把现在 37 个 Templates 一次性全部生成化。

第一阶段只完整做两个：

----------------------------------------
A. Portrait Recipe
----------------------------------------

用户上传：

一张清晰人物照片

Template：

高级 Editorial Portrait / 氛围人物摄影

流程：

看到案例
↓
Try with your image
↓
上传照片
↓
预览
↓
必要 Variables
↓
Generate
↓
Generating
↓
Result
↓
Download
↓
Generate Again

目标：

尽量保留人物身份特征，
改变：

灯光
场景
构图
摄影语言
氛围
服装/造型（视模板而定）

----------------------------------------
B. Product Recipe
----------------------------------------

用户上传：

商品照片

Template：

高级 Commercial Product Photography

流程相同。

目标：

尽量保留商品核心形态，
改变：

背景
灯光
场景
材质表现
广告构图
品牌氛围

先把这两个完整跑通。

做完以后暂停。

不要自己继续把剩余所有模板都接上。

让我真实体验后再决定扩展。

========================================
六、模板详情页新的双入口
========================================

现有 Pack / Template Detail 不推倒。

新增两个清晰入口：

1.

USE THIS RECIPE
用我的图片生成

2.

GET THE PROMPT
获取 Prompt / 模板

两种用户：

高级用户：

买 Prompt / Recipe
然后去自己喜欢的平台使用。

普通用户：

不研究 Prompt
直接上传图片
在本站生成。

这两个能力并存。

不要强迫所有人一定在本站生成。

也不要强迫所有人一定复制 Prompt。

========================================
七、生成工作台
========================================

需要增加一个极简生成 Console / Studio。

但是：

不要做成 ComfyUI。
不要做成 Photoshop。
不要做成工程师面板。

我们的品牌是：

专业结果
低认知负担。

普通用户看到的参数必须非常少。

示例：

上传图片

选择画幅

选择 Variation（如果模板提供）

选择输出质量

高级选项折叠：

Advanced

只有真正必要时才显示：

Reference Strength
Seed
Model
其他高级参数

不要默认展示：

CFG
Sampler
Steps
ControlNet
几十种技术参数

这些参数应该尽量由 Recipe 预设。

我们的价值之一就是：

“参数已经替你调好了。”

========================================
八、图片比例系统必须升级
========================================

当前网站很多成果图偏竖版。

以后不能假设所有 Template 都是 Portrait。

需要建立统一的 Aspect Ratio System。

Template / Artwork 支持：

portrait
landscape
square
wide
auto

并支持具体 ratio：

1:1
4:5
3:4
2:3
3:2
4:3
16:9
9:16
21:9

未来例如：

人物写真：
4:5 / 3:4 / 9:16

商品广告：
1:1 / 4:5 / 16:9

角色三视图：
16:9 / 3:2 / wide

品牌设计板：
landscape

信息图：
portrait / landscape

UI 要做到：

根据作品比例自动适配。

不要：

把横图硬裁成竖图。

需要检查并优化：

PackCard
TemplateCard
Gallery
ArtworkGrid
Examples
Related
BeforeAfter
Library
Reader

推荐：

卡片可以使用预定义展示比例，
但进入 Gallery / Detail 后尽量尊重原始作品 ratio。

允许：

Editorial Grid
Masonry
Mixed Aspect Ratio Layout

保持高级感。

不要因为支持多比例导致页面变乱。

========================================
九、模型策略
========================================

我们的原则：

只接第一梯队模型。

不为了省几分钱牺牲结果质量。

但是：

不站国内/国外模型阵营。

只站：

RESULT QUALITY。

模型层未来可以同时拥有：

国内顶级模型

和：

全球顶级模型。

但普通用户默认不需要面对十几个模型选择。

系统根据：

Template
Input Type
Quality
场景

自动匹配经过我们测试的最佳模型。

前台可以显示：

已为当前模板匹配最佳生成模型。

高级用户可以展开查看：

Tested Models。

核心原则：

模型可以换。

审美标准不能降。

========================================
十、Model Provider Adapter
========================================

非常重要：

页面不能直接绑定某一家模型 API。

建立 Provider Adapter。

统一接口思想：

generateImage({
  templateId,
  recipeId,
  inputImages,
  variables,
  aspectRatio,
  quality,
  modelPreference
})

内部路由到：

Provider A
Provider B
未来其他 Provider

Template 可以保存：

preferredProvider
preferredModel
fallbackProvider
fallbackModel
testedModels
compatibleModels

未来某模型变差或者新模型出现：

只调整 Template Routing / Provider。

不要重写前端。

========================================
十一、模型评测与准入机制
========================================

以后不要凭品牌决定模型好不好。

预留内部 Model Evaluation 思路。

同一套 Benchmark Templates：

Portrait
Product
Typography
Editorial
Character
Commercial

定期测试候选模型。

评估维度：

主体保持
人脸一致性
商品形态保持
审美
构图
材质
文字能力
指令遵循
失败率
速度
成本

达到标准才进入 Production。

这套系统当前不用做完整后台。

但架构和文档要预留。

========================================
十二、收费模式
========================================

现在把收费逻辑定清楚。

不要在 UI 里同时堆很多复杂价格。

第一阶段核心只做三层：

----------------------------------------
1. FREE
----------------------------------------

免费用户：

可以浏览全部案例。

可以使用 Free Templates。

可以复制部分免费 Prompt。

未来新用户可以赠送少量 Credits。

目的：

体验
获客
SEO
分享

----------------------------------------
2. PACK / RECIPE BUYOUT
----------------------------------------

用户可以单独购买一个 Pack。

例如：

Editorial Portrait Pack

一次购买后获得：

当前 Pack 的完整 Recipe
Prompt
Variables
案例
参数
Workflow
Tips
下载资源
在线 Reader 权限

买断不是：

“终身拥有整个网站所有东西”。

而是：

拥有这个具体 Pack。

----------------------------------------
3. CREDITS
----------------------------------------

在线 AI 生成必须消耗 Credits。

原因：

底层模型有真实调用成本。

Credits 和 Pack 权限是两个东西。

用户已经买了 Pack：

获得 Recipe 使用权。

但是在本站生成：

仍然消耗 Credits。

因为：

内容资产成本

和：

模型算力成本

不是同一个东西。

========================================
十三、Pro / Subscription
========================================

未来支持：

Pro Monthly
Pro Annual

但是：

第一阶段不要正式上线复杂订阅。

现在只设计好未来兼容能力。

Pro 的价值应该来自：

持续新增高质量 Templates
持续模型适配
持续 Recipe 更新
部分 Premium Pack 权限
会员专属模板
每月包含一定 Credits
其他高级权益

Important：

Subscription ≠ Credits。

订阅买的是：

内容
更新
权益
持续筛选服务。

Credits 买的是：

实际 AI Generation。

未来可以：

Pro 每月包含一定 Credits。

用完后：

可以继续充值。

但不要让积分和会员概念混乱。

========================================
十四、买断更新策略
========================================

不要承诺：

一次买断，终身无限更新所有内容。

需要 Template / Pack Versioning。

例如：

v1.0
v1.1
v1.2
v2.0

数据增加：

version
changelog
lastTestedAt
testedModelVersion
status

买断用户：

可以获得当前版本和合理范围内的小版本维护。

未来重大：

全新 Pack
重大重做
重大 Version Upgrade

不一定自动永久免费。

具体商业政策以后确定。

当前架构不要把“终身免费更新”写死。

========================================
十五、Prompt 过时问题
========================================

Prompt 会过时不是缺陷。

把它设计成：

持续测试
持续升级
持续维护

的理由。

Template 可以显示：

Last Tested

例如：

最近验证：
2026.xx

Tested with：

某模型

状态：

Active
Needs Review
Deprecated

模型发生重大变化时：

可以重新测试和更新 Recipe。

========================================
十六、Credits 规则
========================================

第一版最小 Credits System：

显示：

Credit Balance

生成按钮显示：

Generate · 8 Credits

具体数字先 Mock，
不要现在确定最终价格。

核心规则必须正确：

生成成功：
扣积分。

模型请求失败：
不扣积分。

系统错误：
不扣积分。

明显超时：
根据最终任务状态决定。

如果成功生成多个结果：

按实际规则结算。

需要避免：

用户反复点击导致重复扣费。

未来真实后端需要：

idempotency。

目前可以先设计接口。
